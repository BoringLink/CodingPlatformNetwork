---

## 2. 业务边界与硬约束

基于当前需求澄清，采用以下硬约束：

1. 系统只关心学生最终认知模板，不存储问卷原始数据，不提供问卷处理能力。
2. 前端 UI 保持现状，不新增复杂交互，不调整视觉结构。
3. 不采集、不存储、不展示性别信息。

设计目标：

1. 支持学习场景 + 学校-年级-班级级联筛选后渲染图谱。
2. 图谱节点仅三类：学生、教师、知识点。
3. 点击学生节点即可查看最终认知模板（维度分数与解释）。

---

## 3. 端到端业务流程

### 3.1 筛选与图谱渲染流程

1. 前端加载场景列表。
2. 前端加载学校列表。
3. 选学校后加载年级列表。
4. 选年级后加载班级列表。
5. 条件齐全后请求图谱接口，渲染节点和边。

### 3.2 学生认知模板查看流程

1. 用户点击学生节点。
2. 前端请求学生认知模板详情接口。
3. 后端返回该学生最新认知模板（最终分值）。
4. 前端在现有详情面板展示维度分数与维度说明。

说明：

1. 不返回问卷题目级数据。
2. 不返回问卷提交记录。
3. 不展示性别字段。

---

## 4. 系统方案总览

### 4.1 架构职责划分

1. 前端负责筛选交互、图谱展示、学生模板详情展示。
2. 后端负责读取结构化节点/交互/认知模板数据并提供查询接口。
3. 离线流程负责将问卷等上游数据转换为最终认知模板后入库。

### 4.2 数据职责边界

1. 在线服务只读取最终模板结果，不处理问卷原始明细。
2. 认知模板表存储总分和维度分，不存题目级映射。
3. 图谱查询只围绕场景、组织维度、时间窗进行过滤聚合。

## 6. 前端对齐方案（保持现有 UI 不变）

前端沿用当前实现，不做 UI 架构改造，重点仅在数据契约对齐：

1. 筛选区继续使用场景 + 学校 + 年级 + 班级级联。
2. 图谱继续渲染三类节点与两类交互边。
3. 点击学生节点继续在现有详情面板展示认知模板。
4. 去除或忽略性别字段渲染。
5. 不增加问卷相关页面或弹窗。

---

## 7. 数据治理与同步策略

1. 问卷到认知模板的映射与计算在离线流程完成。
2. 后端只读取最终模板表，不承担问卷处理。
3. 离线流程应保证每名学生存在最新模板记录。
4. 建议每日或每批次同步后执行完整性校验：
   - 学生节点是否存在对应模板。
   - 模板是否包含全部维度分数。

---

## 8. 性能与稳定性目标

1. 图谱接口按场景 + 组织 + 时间窗进行索引优化。
2. 学生模板详情接口按 studentNodeId 建立快速索引。
3. 热门班级场景组合可短时缓存。
4. 返回数据量控制：节点上限与边上限可配置。

性能目标建议：

1. 图谱接口 P95 < 500ms
2. 学生模板详情接口 P95 < 200ms

---

## 9. 测试与验收

### 9.1 测试项

1. 级联筛选正确性测试。
2. 场景隔离测试（不同场景不串数据）。
3. 三类节点渲染测试。
4. 学生节点点击模板详情测试。
5. 性别字段缺失情况下前端稳定性测试。
6. 问卷原始数据链路不存在性测试。

### 9.2 验收标准

1. 用户可通过场景 + 学校-年级-班级筛选得到正确图谱。
2. 图谱仅展示学生、教师、知识点节点。
3. 点击学生节点可查看最终认知模板。
4. 系统中不存在问卷原始数据存储与展示链路。
5. 前端 UI 与当前版本一致。
