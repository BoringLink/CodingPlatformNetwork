# 数据库架构设计

## 1. 设计概述

基于对真实观测数据的分析，设计了一套完整的数据库架构，用于支持交互网络可视化系统。数据库使用MSSQL，部署在阿里云RDS实例上。

## 2. 表结构设计

### 2.1 学生表 (`students`)

| 字段名 | 数据类型 | 约束 | 描述 |
|-------|---------|------|------|
| `id` | `VARCHAR(50)` | `PRIMARY KEY` | 学生唯一标识 |
| `name` | `VARCHAR(100)` | `NOT NULL` | 学生姓名 |
| `gender` | `VARCHAR(10)` | `NOT NULL` | 性别 |
| `school` | `VARCHAR(200)` | `NOT NULL` | 学校名称 |
| `grade` | `VARCHAR(50)` | `NOT NULL` | 年级 |
| `classId` | `VARCHAR(100)` | `NOT NULL` | 班级 |
| `knowledgeReserve` | `DECIMAL(3,1)` | `NOT NULL` | 知识储备 |
| `learningEngagement` | `DECIMAL(3,1)` | `NOT NULL` | 学习投入 |
| `cognitiveLoad` | `DECIMAL(3,1)` | `NOT NULL` | 认知负荷 |
| `learningMotivation` | `DECIMAL(3,1)` | `NOT NULL` | 学习动机 |
| `computationalThinking` | `DECIMAL(3,1)` | `NOT NULL` | 计算思维 |
| `humanAiTrust` | `DECIMAL(3,1)` | `NOT NULL` | 人机信任度 |
| `learningMethod` | `DECIMAL(3,1)` | `NOT NULL` | 学习方法倾向 |
| `learningAttitude` | `DECIMAL(3,1)` | `NOT NULL` | 学习态度 |
| `createdAt` | `DATETIME` | `NOT NULL DEFAULT GETDATE()` | 创建时间 |
| `updatedAt` | `DATETIME` | `NOT NULL DEFAULT GETDATE()` | 更新时间 |

| `teachingClass` | `VARCHAR(100)` | `NOT NULL` | 教学班级 |

| `updatedAt` | `DATETIME` | `NOT NULL DEFAULT GETDATE()` | 更新时间 |

### 2.3 知识点表 (`knowledge_points`)

| 字段名 | 数据类型 | 约束 | 描述 |

| `id` | `VARCHAR(50)` | `PRIMARY KEY` | 知识点唯一标识 |

### 2.4 交互表 (`interactions`)

| 字段名 | 数据类型 | 约束 | 描述 |
|-------|---------|------|------|
| `id` | `VARCHAR(50)` | `PRIMARY KEY` | 交互唯一标识 |
| `sourceId` | `VARCHAR(50)` | `NOT NULL` | 源节点ID |
| `targetId` | `VARCHAR(50)` | `NOT NULL` | 目标节点ID |
| `sourceType` | `VARCHAR(20)` | `NOT NULL` | 源节点类型 (STUDENT/TEACHER/KNOWLEDGE) |
| `targetType` | `VARCHAR(20)` | `NOT NULL` | 目标节点类型 (STUDENT/TEACHER/KNOWLEDGE) |
| `value` | `DECIMAL(5,2)` | `NOT NULL` | 交互强度 |
| `type` | `VARCHAR(20)` | `NOT NULL` | 交互类型 (PHYSICAL/PLATFORM) |
| `interactionType` | `VARCHAR(20)` | `NULL` | 具体交互类型 (like/comment) |
| `createdAt` | `DATETIME` | `NOT NULL DEFAULT GETDATE()` | 创建时间 |
| `updatedAt` | `DATETIME` | `NOT NULL DEFAULT GETDATE()` | 更新时间 |

| `updatedAt` | `DATETIME` | `NOT NULL DEFAULT GETDATE()` | 更新时间 |

### 3.2 关键关系

1. **学生与教师**：通过`interactions`表建立多对多关系
2. **学生与知识点**：通过`interactions`表建立多对多关系
3. **学生与学生**：通过`interactions`表建立多对多关系（基于点赞和评论）
4. **教师与教师观察**：通过`teacher_observations`表建立一对多关系

## 4. 索引设计

### 4.1 聚集索引

- `students.id`
- `teachers.id`
- `knowledge_points.id`
- `interactions.id`
- `teacher_observations.id`

### 4.2 非聚集索引

- `students.school` + `students.grade` + `students.classId`：加速按学校、年级、班级查询
- `interactions.sourceId` + `interactions.sourceType`：加速查询节点的所有出边
- `interactions.targetId` + `interactions.targetType`：加速查询节点的所有入边
- `teacher_observations.teacherId`：加速查询教师的观察数据
- `teacher_observations.school` + `teacher_observations.grades`：加速按学校和年级查询教师观察数据

## 5. 分区设计

对于大型表，建议使用分区策略以提高性能：

- **interactions表**：按`createdAt`字段分区，每个月一个分区

## 6. 数据迁移策略

1. **初始数据导入**：
   - 使用xlsx skill和xlsx MCP处理Excel文件
   - 批量导入数据到对应表中
   - 验证数据完整性和一致性

2. **增量更新**：
   - 定期从Excel文件或其他数据源更新数据
   - 使用唯一标识符避免重复数据
   - 记录数据更新日志

## 7. 安全设计

1. **访问控制**：
   - 使用最小权限原则配置数据库用户
   - 限制直接数据库访问，通过API访问数据

2. **数据保护**：
   - 敏感数据加密存储
   - 定期备份数据库
   - 实施数据审计

3. **性能安全**：
   - 使用参数化查询防止SQL注入
   - 实施查询超时和资源限制

## 8. 性能优化

1. **查询优化**：
   - 使用索引加速查询
   - 避免全表扫描
   - 优化复杂查询

2. **存储优化**：
   - 合理设置字段长度
   - 使用适当的数据类型
   - 定期清理无用数据

3. **连接优化**：
   - 使用连接池管理数据库连接
   - 优化连接参数

## 9. 总结

本数据库架构设计基于对真实观测数据的分析，充分考虑了系统的功能需求和性能要求。通过合理的表结构设计、关系设计和索引设计，确保了系统能够高效地存储和查询数据，为交互网络可视化提供有力支持。
