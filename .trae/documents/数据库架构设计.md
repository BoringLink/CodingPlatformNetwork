# 数据库架构设计

## 1. 设计概述

基于对真实观测数据的分析，设计了一套完整的数据库架构，用于支持交互网络可视化系统。数据库使用MSSQL，部署在阿里云RDS实例上。

## 2. 表结构设计

### 2.1 学生表 (`Students`)

| 字段名 | 数据类型 | 约束 | 描述 |
|-------|---------|------|------|
| `id` | `VARCHAR(50)` | `PRIMARY KEY` | 学生唯一标识 |
| `name` | `VARCHAR(100)` | `NOT NULL` | 学生姓名 |
| `gender` | `VARCHAR(10)` | `NOT NULL` | 性别 |
| `school` | `VARCHAR(200)` | `NOT NULL` | 学校名称 |
| `grade` | `VARCHAR(50)` | `NOT NULL` | 年级 |
| `class_id` | `VARCHAR(100)` | `NOT NULL` | 班级 |
| `knowledge_reserve` | `DECIMAL(3,1)` | `NOT NULL` | 知识储备 |
| `learning_engagement` | `DECIMAL(3,1)` | `NOT NULL` | 学习投入 |
| `cognitive_load` | `DECIMAL(3,1)` | `NOT NULL` | 认知负荷 |
| `learning_motivation` | `DECIMAL(3,1)` | `NOT NULL` | 学习动机 |
| `computational_thinking` | `DECIMAL(3,1)` | `NOT NULL` | 计算思维 |
| `human_ai_trust` | `DECIMAL(3,1)` | `NOT NULL` | 人机信任度 |
| `learning_method` | `DECIMAL(3,1)` | `NOT NULL` | 学习方法倾向 |
| `learning_attitude` | `DECIMAL(3,1)` | `NOT NULL` | 学习态度 |
| `created_at` | `DATETIME` | `NOT NULL DEFAULT GETDATE()` | 创建时间 |
| `updated_at` | `DATETIME` | `NOT NULL DEFAULT GETDATE()` | 更新时间 |

### 3.2 关键关系

1. **学生与教师**：通过`Interactions`表建立多对多关系
2. **学生与知识点**：通过`Interactions`表建立多对多关系
3. **学生与学生**：通过`Interactions`表建立多对多关系（基于点赞和评论）
4. **教师与班级**：通过`TeacherClassMappings`表建立一对多关系，支持一个教师教学多个年级和多个班级
5. **教师与教师观察**：通过`TeacherObservations`表建立一对多关系
6. **知识点与知识点**：通过`KnowledgePoints`表中的`parent_id`字段建立自引用的一对多关系，支持知识点的层级结构
7. **知识点与知识点（关联）**：通过`KnowledgePoints`表中的`related_knowledge_ids`字段建立多对多关系，支持知识点之间的横向关联

## 4. 索引设计

### 4.1 聚集索引

- `Students.id`
- `Teachers.id`
- `TeacherClassMappings.id`
- `KnowledgePoints.id`
- `Interactions.id`
- `TeacherObservations.id`

### 4.2 非聚集索引

- `Students.school` + `Students.grade` + `Students.class_id`：加速按学校、年级、班级查询
- `Teachers.school`：加速按学校查询教师
- `Teachers.teaching_grade` + `Teachers.teaching_class`：加速按教学年级和班级查询教师
- `TeacherClassMappings.teacher_id`：加速查询教师的所有教学班级
- `TeacherClassMappings.grade` + `TeacherClassMappings.class_id`：加速按年级和班级查询教师
- `KnowledgePoints.grade`：加速按年级查询知识点
- `KnowledgePoints.type`：加速按类型查询知识点
- `KnowledgePoints.parent_id`：加速查询上级知识点的子知识点
- `Interactions.source_id` + `Interactions.source_type`：加速查询节点的所有出边
- `Interactions.target_id` + `Interactions.target_type`：加速查询节点的所有入边
- `TeacherObservations.teacher_id`：加速查询教师的观察数据
- `TeacherObservations.school` + `TeacherObservations.grades`：加速按学校和年级查询教师观察数据

## 9. 命名规范说明

为了确保数据库设计的一致性和可维护性，本架构采用以下命名规范：

### 9.1 表名命名规范
- 使用帕斯卡命名法（PascalCase）：首字母大写，后续每个单词首字母也大写
- 表名使用复数形式，表示数据集合
- 避免使用下划线和特殊字符
- 表名长度限制在30个字符以内

### 9.2 字段名命名规范
- 使用蛇形命名法（snake_case）：全部小写，单词之间使用下划线分隔
- 字段名应简洁明了，能够清晰表达字段的含义
- 主键字段统一命名为`id`
- 外键字段命名为`[关联表名小写]_id`，如`teacher_id`
- 日期时间字段使用`created_at`和`updated_at`

### 9.3 索引命名规范
- 聚集索引：`[表名小写]_id`
- 非聚集索引：`[表名小写]_[字段1]_[字段2]...`
- 唯一索引：在索引名后添加`_u`
- 非唯一索引：在索引名后添加`_n`
- 聚集索引：在索引名后添加`_c`
- 非聚集索引：在索引名后添加`_n`

## 10. 总结

本数据库架构设计基于对真实观测数据的分析，充分考虑了系统的功能需求和性能要求。通过合理的表结构设计、关系设计和索引设计，确保了系统能够高效地存储和查询数据，为交互网络可视化提供有力支持。

同时，严格遵循MSSQL数据库命名规范，使用帕斯卡命名法统一表名和字段名，提高了代码的可读性和可维护性，便于团队协作和后续开发。
